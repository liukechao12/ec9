> 2026-10-31 首次系统性排查与改造。改动集中在两个文件，**全站 11 个页面生效**：

> - `backend/public/h5/ec9/css/style.css`（`--vh`、安全区、字体缩放、X5 兼容）

## 一、页面怎么适配不同屏幕的（先理解这个，后面才看得懂）

设计稿是 **375px 宽**。做法是 `#app` 永远按 375px 布局，再整体缩放到屏幕宽度：

```js
var s = Math.min(clientWidth / 375, 1.6);   // 缩放比
// 支持 zoom 的（iOS Safari / iOS 微信）：zoom 会算进布局，最省心
app.style.zoom = s;
// 不支持的（Android 微信 X5 内核等）：transform: scale + 外边距补偿占位
app.style.transform = "scale(" + s + ")";
```

**分支差异是所有坑的来源**：`zoom` 会真实改变布局尺寸，`transform` 不改变布局盒（盒还是死的 375px），
必须手动用外边距把"被缩掉/多出来"的空间补回来，补偿量算错就是肉眼可见的错位。

## 二、这次修掉的问题（按严重程度排序）

### 1. 窄屏上页面能左右拖动（所有页面，Android 微信实测 8px）

**现象**：360px 屏（华为/小米常见）上，页面右边多出一截，手指能横向拖动。

**根因**：`transform-origin` 原本是 `top center`。`#app` 布局盒固定 375px，在 360px 视口里盒比视口宽，
以**盒中心**为原点缩放后，视觉上整体右移 `(375 - 375×s)/2 ≈ 8px`。

**修法**：
```js
app.style.transformOrigin = "top left";                        // 不再按盒中心缩放
app.style.marginLeft  = Math.max(0, (vw - 375 * s) / 2) + "px"; // 宽屏（s 被 1.6 卡住）时居中
app.style.marginRight = Math.min(0, vw - 375) + "px";           // 负右边距吃掉布局盒多出的宽度
```

### 2. ⚠️ 千万别用 `overflow-x: hidden` 兜横向溢出

试过一次，直接造成回归，已回滚。原因：

设置 `overflow-x: hidden` 会把 `overflow-y` 从 `visible` 强制变成 `auto`，
**滚动容器从 `documentElement` 变成 `body`**，后果是：

| 指标 | 正常 | 加了 overflow-x:hidden |
|---|---|---|
| `documentElement.scrollHeight` | 内容全高（17349） | **一屏高（640）** |
| `window.scrollY` | 正常递增 | **恒为 0** |
| 键盘回弹复位 `window.scrollTo()` | 生效 | **失效** |
| iOS 惯性滚动 | 有 | 丢失 |

判断方法：`document.documentElement.scrollHeight` 若等于 `clientHeight` 而内容明显更长，就是踩了这个坑。

### 3. `100vh` 在微信里偏大，底部按钮被微信 UI 挡住

微信 iOS 的 `100vh` 是**含浏览器 UI 与底部安全区的大视口高度**，比真正看得见的区域高一截
（iPhone 14 Pro 上约高 80~130px）。用它做 `min-height`，页面底部会顶到微信工具栏/小黑条底下。

**修法**：JS 把 `window.innerHeight`（真实可视高度）写进 CSS 变量 `--vh`，CSS 全部改用：

```css
:root { --vh: 100vh; }                       /* JS 没跑起来时的兜底 */
min-height: calc(var(--vh, 100vh) / var(--z, 1));
```

⚠️ 键盘弹起时 `innerHeight` 会缩水，此时**不要**更新 `--vh`（否则页面上跳），已有 `isTyping()` 判断。

### 4. 底部内容被 iPhone 小黑条压住

项目原先**完全没有** `env(safe-area-inset-bottom)`。iPhone X 及以上的 34px 小黑条会压住最后一行。

已加（都写成两行，老浏览器不支持 `env()` 时自动回退到上一行）：

```css
padding-bottom: 30px;
padding-bottom: calc(30px + env(safe-area-inset-bottom, 0px));
```

覆盖：`.sheet`、`.agree-page`（协议页）、`#app.tk-page`（选票页）、`.eticket-wrap`（电子票）、`.ec9-toast`。

### 5. 异步内容（法务文档）加载后适配不重算

协议页正文是 `fetch('/api/legal/...')` 拿的，`fitViewport` 原本只在 300ms / 1200ms 各跑一次。
弱网下内容晚于 1200ms 到位，`transform` 分支的高度补偿就用的是旧值。

**修法**：加 `ResizeObserver` 监听 `#app`，高度一变自动重算（rAF 节流，避免抖动）。

### 6. iOS 微信软键盘收起后页面不复位

WKWebView 不会自动还原滚动位置，表现为底部留一条空白、`position: fixed` 元素错位。

**修法**：`focusin` 时记下 `scrollY`，`focusout` 后 150ms 还原并重新 `fitViewport()`。

### 7. 上下回弹露出白边

`html/body` 背景是白色，蓝底页面（协议/结果/电子票）在 iOS 微信橡皮筋回弹时会露出两条白边。

**修法**：`fitViewport` 里读 `#app` 的实际背景色同步给 `html`/`body`。

### 8. 其它

| 项 | 说明 |
|---|---|
| `-webkit-text-size-adjust: 100%` | 微信「字体大小」设置 / 横屏切换不再撑破版式 |
| `inset: 0` → 展开写 | `inset` 简写要 Chrome 87+，X5 内核偏老 |
| `pageshow` 补一次适配 | 微信 iOS 走 bfcache 返回时不触发 `load` |

## 四、还没做的（需要昊哥拍板）

### 🔴 微信内支付走不通（缺网页授权）

现状链路：

```
pay.html 点「立即支付」 → POST /api/payment/group/:orderNo/pay { pay_token, openid }
                        → 后端：有 openid 才走 JSAPI，否则 400「请使用扫码支付」
```

前端 `WeixinJSBridge.invoke('getBrandWCPayRequest')` 已经写好了，**但项目里没有任何获取 openid 的链路**
（全库搜不到 `snsapi` / `oauth2` / 授权回调）。所以微信里点支付 → 拿不到 openid → 回落扫码。

要打通需要：

1. 公众号（**服务号**，且已微信认证）的 `AppID` + `AppSecret`
2. 公众号后台 → 设置 → 网页授权域名，填 `ec9.51world.com.cn`（需下载校验文件放到站点根目录）
3. 后端加两个接口：
   - `GET /api/wechat/authorize?redirect=<回跳页>` → 302 到 `snsapi_base` 授权
   - `GET /api/wechat/callback?code=xxx` → 换 openid，写 Cookie，跳回原页面
4. 前端支付时把 openid 带上

`scope` 用 `snsapi_base`（静默授权，用户无感知）就够支付用，不需要 `snsapi_userinfo`。

### 🟡 微信分享卡片（JSSDK）

现在分享出去是默认标题 + 空白缩略图。要自定义需引入 `jweixin` 并 `wx.config`（同样要 AppID/AppSecret + 域名白名单）。

### 🟡 协议正文段落缩进不统一

Word 原稿里有的段落有首行缩进、有的没有，转换后如实保留。要统一得改 docx 源文件或在 CSS 里强制
（会影响所有段落，建议让法务在 Word 里统一）。
