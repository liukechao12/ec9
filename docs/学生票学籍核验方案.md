# EC9 学生票 · 学籍在线核验方案

> 状态：**待昊哥确认后实施**（当前未改任何代码）
> 决策记录：2026-10-30 昊哥拍板 —— ①走全自动第三方 API ②核验结果「不在籍」→ **自动驳回**

---

## 一、结论与选型

**学信网官方不对企业开放 API**（只有个人自查 / 对公授权认证报告 30 元·1-3 工作日 / 在线验证报告人工核验）。
要做自动化只能走第三方，底层数据均来自学信网 + 教育部学籍库。

| 候选 | 产品 | 价格 | 适配度 |
|---|---|---|---|
| **天远 API** | **学籍核验政务V1（IVYZX7J9）** | **3.2 元/次** | ✅ **选定**，返回「在籍/不在籍」，正是我们要的 |
| 天远 API | 学籍学历核验实时版 | 4.5 元/次 | 字段更全（学校/专业/学制），但我们不需要，且更贵 |
| 阿里云市场（千数通） | 学历核验 | ≈2.2 元/次 | ❌ **不适用**：查的是「毕业学历」，在校生未毕业会返回无记录 → 全员误杀 |
| 羽山 / 九章数盾 | 学籍核验 | 需商务报价 | 备选 |

### ⚠️ 关键提醒
买之前一定确认是「**学籍/在籍**核验」而不是「**学历**核验」。学生票面向**在校大学生**，学历接口查不到他们。

## 二、接口规格（天远 IVYZX7J9）

```
POST https://api.tianyuanapi.com/api/v1/IVYZX7J9?t=<13位毫秒时间戳>
Header: Access-Id: <账号 Access-Id>
Body:   { "data": "<base64>" }
```

**加密**：业务参数 JSON → AES-128-CBC / PKCS7 / 随机 16 字节 IV → IV 拼在密文前 → Base64。
密钥 = 平台下发的 Access Key（16 进制字符串）。响应 `data` 字段同样方式解密。

**入参**（只要两项，符合最小必要原则）：
```json
{ "name": "张三", "id_card": "110101200301011234" }
```

**返回**：`{ "status": 1 }` → 1=在籍，0=不在籍
> 另有版本返回 `resultCode`：0=无法判断 / 1=不在籍 / 2=在籍。
> **联调时两种字段都要兼容**，以实测为准。

**外层响应**：`{ code, message, transaction_id, data }` —— `transaction_id` 用于对账与审计留档，必须落库。

## 三、业务流程

```
报名提交（票种 is_student=1）
   ↓
前端校验：姓名非空 + 身份证 18 位（含校验位算法）
   ↓
后端：身份证号 AES 加密落库（不明文）
   ↓
调学籍核验 API（超时 8s，失败重试 1 次）
   ├─ 在籍  → 自动 approved → 学生票 ¥0 → 直接 paid → 发「报名成功」短信
   ├─ 不在籍 → rejected，reject_reason =「学籍核验未通过」
   └─ 接口异常/超时/无法判断 → 保持 submitted 转人工审核（见下）
```

### 🔴 必须保留的降级口子
「不在籍自动驳回」是昊哥定的，但**接口异常 ≠ 不在籍**。以下三种情况一律**转人工**，不能自动驳回：

1. API 超时 / 5xx / 鉴权失败
2. 返回「无法判断」（resultCode=0）
3. 应届毕业生 9-10 月入学期，学籍库入库滞后

否则接口一挂，当天所有学生票报名全部被误杀。

### 多人代报（group）
整单里只有选了学生票的成员需要填身份证号并核验；全员核验通过才整单通过，任一不在籍 → 该成员 rejected，其余正常。

## 四、数据改造

### 1. `ec9_registrations` 新增列
| 字段 | 类型 | 说明 |
|---|---|---|
| `id_card_enc` | TEXT | 身份证号 AES 密文（复用 `utils/secretCrypto`，**绝不明文**） |
| `student_verify_status` | SMALLINT | 0未核验 / 1在籍 / 2不在籍 / 3异常待人工 |
| `student_verify_at` | DATETIME | 核验时间（30 天内复用，防重复扣费） |
| `student_verify_txid` | VARCHAR(64) | 接口流水号，对账与审计 |

### 2. 新建 `ec9_student_verify_config`（单行配置）
`enabled` TINYINT、`config_encrypted` TEXT（JSON: access_id / access_key，AES 密文）、`updated_at`
→ 照抄 `smsConfigService` 模式：后台可改、对外只回掩码、改完免重启。

### 3. 新建 `ec9_student_verify_logs`（审计流水）
`registration_id`、`guest_id`、`txid`、`name_mask`（张三→张*）、`result_code`、`result_desc`、`cost_ms`、`created_at`
→ **不存身份证明文**，只存掩码。
